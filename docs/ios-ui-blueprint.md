## Detail presentation flow — accepted 2026-10-01

Concrete phone review established the navigation flow before further surface refinement:

- Map owns one bottom results/detail container. Overlapping route hits open results; choosing a result replaces that destination with the shared detail. A single route can open detail directly. Results Back restores its exact scroll position and retains selection/active route/camera context. There is no selector beneath a separate modal detail sheet.
- List activity inspection overlays the existing List with a native detented sheet. Dismiss returns to its retained scroll position without changing selection or active route. The same identity/metrics/recorded-details/action panel serves both hosts; only Map adds results navigation.
- Map collapse changes the existing container to a compact summary; expansion restores its current destination. Results selection actions live with results/summary, while activity actions live with detail. Show on map is explicit; in Map it collapses this container before requesting a route fit.
- Map detail uses native horizontal scroll paging: content follows the finger, cancelled drags retain focus, and completed page turns commit the next activity. Arrows keep a stable appearance during a drag and use the same native pager with matching forward/reverse direction; Reduced Motion skips arrow sliding. Vertical content scroll remains independent, and horizontal header drags do not resize the panel. Single detail puts collapse beside its activity heading instead of reserving an empty navigation row.
- Map controls stay in one horizontal group anchored below navigation at the top-right of the viewport. Opening, closing or resizing results does not move them. The Map/List switch uses matching capsule shapes.
- Phone Map owns one frosted regular-material surface, attached to the bottom with 4pt side margins and rounded top corners. The outer host owns the home-indicator inset once; fixed actions sit above it. Map detail adds no opaque nested background. List retains its native opaque sheet. Neither host adds a generic Activity title or Done toolbar. Activity names wrap; long detail content scrolls above reachable actions. Routine sync status, progress, timestamps and refresh/pause controls live under Account → Settings → Activity Data; Sync Details opens within Settings. Map/List reserve no persistent sync bar. Blocking loading, sign-in and empty-library states retain their contextual recovery action.
- Wide Map uses its existing edge panel and wide List uses inline detail. Stats activity inspection will reuse the shared detail by identity when that surface lands.

These rules are implemented in the working #270 revision. They do not change route-picking/selection contracts. Other configuration and menu flows remain with their screen owners; this revision does not claim completion of the navigation shell (#254) or full #257 scope.

## Accepted product direction

1. **Three equal primary destinations:** Map, List, Stats in a native tab bar. Keep all three mounted as needed for their retained contexts. The top bar names the destination; it has Account and Filters, without a second competing destination picker. On iPad, use the system's adaptive tab placement; the board's tab placement is illustrative, not a custom substitute for system behavior.
2. **One search/filter owner:** activity-name search above List/Stats; on Map the compact search field shares the top chrome budget. In shallow landscape or accessibility layouts collapse search to the Filters destination. Search, sport, binary and numeric restrictions apply across destinations. Stats replaces date entry with its period explanation; retained browsing dates remain visible as saved context, not active Stats constraints.
3. **Local control families:** List owns sort/display/selection/summaries. Map owns layers/camera/area selection/results. Stats owns each tile's metric, period, expansion and history. Account owns connection and detailed timestamps. No detached global row of unrelated controls.
4. **One shared detail content:** activity identity and independently available metrics, chart/gallery extension slots, fixed action area. A row or Stats activity link inspects without selecting. Checkbox/selection tools select. Show on map alone performs the explicit destination/activation/frame transition.
5. **Quiet status:** no always-visible success or old-cache warning card. Show actionable recovery once near the content it affects; retain authorized content and context. Account contains explanatory sync detail. Never use visual simplification to change retry/expiry semantics.
6. **Stats preserves its stabilized hierarchy:** Now → This year → Patterns, all eleven visible tiles. Primary tiles own large headlines; Records uses its record rows without a competing aggregate headline. Native charts provide touch inspection and accessible data equivalents. No extra Rest days, totals or speed-trend screen is introduced.

These decisions establish the implementation direction. Screen-level details remain open to concrete review and adjustment; the board is not a pixel-exact specification. The acceptance record is in #252, following review of the board and locally captured authenticated web screens at Mac and iPhone viewport sizes.

Camera fitting excludes safe areas, attribution, controls and current result-panel occupied rectangles. Fit selection / Fit filtered / Show on map are explicit events. Expanding a panel updates occlusion but does not trigger a new fit. Collapsing hides neither selection identity nor the way back to results. Expanded result heights cannot force map gestures to compete with scrolling in the same region.

Status and content budget: one compact inline recovery row at default size, with wrapping and a Details action at large text. If a multi-line explanation would consume the map budget, use a short “Offline · saved activities” row and move explanation to Sync details. Empty/filter-empty states replace the relevant content region. A retained-data failure does not replace a populated List/Stats with an empty error screen.

## Information, colors and emphasis

Use the web's semantic vocabulary and category palette: BC/XC ski `#1982C4`, trail/hike `#FF595E`, run `#FFCA3A`, ride `#8AC926`, miscellaneous `#6A4C93`. Brand/action accent is the existing `#2E6BC9`, with semantic accessible contrast adaptation on system backgrounds. Yellow/green swatches are not small text on white. Native labels remain primary text; color is supplementary.

- **Active route:** strongest route weight + labelled active result. **Selected:** checkbox/checkmark and modest surface emphasis; hidden selected count remains explicit. **Inspected:** open detail + focus/outline/expanded context; do not imply it is selected. Destination, filter-active and selection feedback use distinct labels/shapes, never color alone.
- **Primary action:** explicit outcome with textual label, usually Show on map. **Secondary:** labelled native menu/button, neutral surface. **Destructive:** separate destructive role and appropriate existing confirmation, not sport/brand color. Successful sync is not an accent CTA.
- **List default:** compact activity name; sport + local date/time on one supporting line; distance, elapsed duration and elevation gain as inline values/units with small symbols, rather than repeated stacked labels. Selection uses explicit checkboxes separate from sport symbols. The toolbar combines selection count/actions with short Sort and Columns controls. Additional metrics remain configurable and available in detail. Default ID descending preserves contract semantics even when date order seems more familiar.
- **Detail:** headline numbers first, supporting labels/context below, matching the web card's grouping: distance with recorded speed context; moving time with elapsed time; elevation gain with independently recorded minimum/maximum; weighted power with average/maximum context. Additional recorded HR/energy/power values use the same compact grid; full recorded metadata remains reachable through a native disclosure. Do not hide one measured field because another is null. Show “—” with unavailable meaning; zero displays normally. Phone uses two metric columns, wide hosts adapt, and accessibility text uses a single column.
- **Stats:** Distance / Moving time / Elevation / Activities where supported. Time always means moving time; duration filter always elapsed. Overview uses contract display precision (whole distance/elevation, hours per contract), not List's distance-to-one-decimal precision. Legend/range labels are visible, not hover-only.
- **Surfaces:** native grouped system backgrounds for list/form/detail, restrained separators and rounded grouping. Map controls may use regular material with sufficient contrast. Do not put every text label in a floating capsule or use material over all data cards.

## Essential journeys

**Find → filter → select → inspect → Show on map:** open List, enter a name, adjust sports/restrictions in Filters, return to the same list context, select using a checkbox, inspect using the row's content, then Show on map. Inspection does not alter selected IDs. Show on map adds and activates the target while retaining other selection and frames once. Returning restores List's sort/density/metrics/scroll anchor. The board exercises these state distinctions; production filter controls/calculations remain their owners.

**Hidden selection:** choose multiple IDs, apply a restrictive filter, show `N selected · H hidden by filters`. Visible selected routes/results obey the predicate. Clearing selection includes hidden IDs. If a Stats/other detail target is hidden by the browsing filter, offer **Clear filters and show on map** explicitly; Cancel preserves the origin and filter. The board includes this confirmation, not a silent reset.

**No GPS:** inspect and other supported actions remain available; Show on map is disabled with “No GPS route recorded.” A placeholder route must not be invented. Known photos may still exist. The reference stats fixture has no geometry; its native reference naturally demonstrates this state.

**Stats → expand → day → activity → return:** navigate to Stats with saved browsing dates; read tile-owned period explanation. Expand Calendar, keep legend visible, choose a day (including empty days), inspect an identified activity, dismiss back to that day's context, then collapse back to the same overview anchor. Nested dismiss/back/Escape closes activity before expansion. Show on map remains explicit. No Stats link implicitly selects map/list rows.

**Old authorized offline cache:** content remains usable; Settings owns sync/offline details and informational timestamps. Server wait disables retry until deadline. Browsing shows contextual recovery only when loading/sign-in/library state blocks content. Real session expiry/account/deployment transition clears/fences data and derived Stats rather than showing stale authorized results.

## Stats layout handoff

All eleven tiles appear in source catalogue order. On phone use one readable column. On iPad use two columns at 820pt, preserving section ordering. Compact tiles are content-sized; expand via an explicit labelled corner action. Phone expansion uses an adaptive sheet/full-screen host that keeps origin tile/scroll/metric/history in mounted state; iPad may expand inline across the section. Outside scrolling/control use does not collapse expansion. Reduced Motion skips competing reflow animation.

| Section / tile                  | Native presentation / complete controls                                                                                                                                                                              |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Now / This week                 | Primary value, weekday bars, future-day unavailable marks; Distance/Moving time/Elevation; no expansion                                                                                                              |
| Now / Training volume           | Last 28 days + prior 28 comparison, 12-week trend, four-full-week average; metric switch incl. Activities; expansion owns weeks/months pages and all years, sport breakdown and displayed-period total               |
| Now / This month                | Month-to-date label with partial marker; prior-month aligned comparison; metric switch; expansion previous/next/reset and cumulative history                                                                         |

| This year / Year-end projection | Secondary projected total, daily mean, prior whole-year context; projection wording stays explicit; metric switch, no expansion                                                                                      |
| This year / Records             | Distance/moving-time/elevation activity records + greatest week as labelled rows, no new aggregate headline; expansion all-time records, activity links and complete-window 30-day context                           |
| Patterns / Activity calendar    | Active-day count, visible sport/intensity legend, rolling-year month rows, mixed-day shape cue; Sport default, then metrics; expansion rolling/selected-year navigation. Day activity inspector reuses shared detail |
| Patterns / Consistency          | 12/52-week switch, fixed 0–7 active-day scale and incomplete current-week marker; expansion same choice and labelled weekly table. 52-week chart pans with touch/accessible value navigation                         |
| Patterns / Sport mix            | Moving-time shares with fixed category positions, range switch This year/All time; explanation for one/no measured sport; expansion complete sport metric table                                                      |
| Patterns / Hilliness            | Metres per 100km, prior rolling-year comparison and monthly trend; expansion chart/table + identified five hilliest eligible activities (≥5km)                                                                       |

Touch inspection must announce exact date/period, value/unit and incomplete marker. Provide a visible data-table/list alternative for every expanded chart; VoiceOver exposes the same data in order. Calendar legends remain present while day detail is shown; mixed sport is labelled and shaped. Future is unavailable, not zero. Incomplete loaded history is disclosed before numerical claims about absence.

Design/capture cases S0–S9 keep the contract's dataset-owned dates: empty `2026-01-05`; sparse/null/zero/ties `2026-03-31`; leap history `2024-03-01` (alternate leap YTD `2024-02-29`); record boundaries `2026-01-01`. Proposed overview/reference capture uses sparse with its actual date. Scenarios in the board illustrate composition, not new formula fixtures. Use both unchanged calculation corpora in #262.
