# iOS browsing UI blueprint

Design handoff for [#252](https://github.com/wirhabenzeit/activitymap/issues/252), dated 2026-09-30. Open the self-contained [interactive review board](ui-blueprint/index.html) in a browser. It contains proposed phone, landscape, iPad, dark and large-text layouts, scenario switches and current reference images. It makes no network requests.

**Status: direction accepted on 2026-09-30.** The repository owner accepted revision `0f6e87ed17bf8757fd6f8011cef847ffc379e079`; [the recorded decision](https://github.com/wirhabenzeit/activitymap/issues/252#issuecomment-5919290478) calls for closer web presentation with sensible native SwiftUI controls, and detailed visual refinement through working screens. ## Implemented browsing flow — current as of 2026-10-02

The flow below was accepted through concrete phone review on 2026-10-01 (#270) and revised by the drafts merged in #278 on 2026-10-02. Items marked **draft** are working prototypes awaiting owner/device review, not accepted direction. [Component handoff](ios-ui-components.md) records implementation detail and evidence.

**Shell and filters (#254)**

- Navigation bar uses the web navigation brand blue `#1976d2` with white Filters, mode and Account controls (**draft**, tracked with visual identity in #272). Filters sit leading, with a filter glyph and an active-filter count badge (VoiceOver: “Filters, 3 active”); Account sits trailing and shows the user's 32pt avatar in a 44pt target, falling back to the person icon. The Map/List picker uses a flat selected capsule rather than glass.
- Regular windows ≥760pt with standard text keep a 52pt leading filter rail: one icon per filter, marked while active, each opening only that filter in a popover (#354). The filter button expands the rail into the 320pt panel: a column beside one-column content (Map, Stats, List without detail), floating over List and its detail where the panel would squeeze them (portrait). Opening an activity collapses an expanded column back to the rail. Destinations, List detail and Stats focus pages never show or hide filters. Compact windows and accessibility text use a native filter sheet (**draft**).
- Filter order: search, sport groups, dates, then measurements and Any/Yes/No rows. Sport groups are compact multi-select chips using the shared web symbols/colours with explicit all/none/mixed states and an Only action. Measurement filters are two-ended range sliders with a labelled scale, reset, no text fields and no Apply button; drags commit on release. Existing one-sided predicates remain valid. This is a deliberate native divergence from web's single-sided inequalities (**draft**).
- Filters/Account wait for the native Map sheet to dismiss before presenting; Map selection is suspended for the whole shell-sheet presentation and restored afterward.

**List (#255, #273)**

- Compact rows: checkbox, identity/date/sport block, inline metrics and an actions menu. Totals and the totals picker remain removed pending redesign. The selection/Sort/Columns toolbar now uses an opaque system background matching the table header (replacing the earlier thin-material glass). The Columns sheet stays open while metric/layout changes switch between table and stacked branches.
- Column fit uses one width budget for default and optional metrics: 104pt identity reserve on compact widths, 180pt on wide widths; wide rows add a separate sortable local-date column. Overfull selections, explicit scrolling metrics and accessibility text keep their fallback layouts.
- Phone inspection pushes a native detail destination. Native Back, swipe-back and the accessible escape action return to the same retained list at its exact offset, with filters, sort/display settings, selection and active route unchanged. No neighbouring-activity pager; vertical neighbour browsing is deferred.
- Regular width ≥760pt, standard text: List uses the full width until an activity is inspected, then opens an adjacent 340–420pt detail pane while keeping ≥400pt for browsing. Closing restores the full width. An already-pushed detail stays open through width changes until Back. The filter rail leaves room for the adjacent pane on every portrait iPad from 820pt; filters never take that room, so inspection never borrows a filter column (#354). Inspected rows use a blue tint, thin top/bottom borders and a 3pt leading bar; selected rows use a neutral grey background with the check badge. Combined rows keep both treatments. VoiceOver announces inspection and selection separately. Map results use the same treatment for their active row (#356); neighbour stepping remains separate work.

**Shared detail (#257)**

- One identity/metrics/recorded-details/action panel serves every host. Primary values are distance, moving time, elevation gain and weighted power, with related context underneath; other recorded metrics use a compact secondary grid. Profile and photo slots sit after metrics and before description/recorded details, ready for #217/#218 without placeholder content.
- The activity name is the content heading, without a generic Activity title, Done control or detent adjustment.
- The fixed bottom action is host-specific: **Show on map** from List, **Fit route** from Map. Fit route collapses detail while reserving the medium panel footprint, so reopening detail does not cover the fitted route. Future working edit/refresh/share actions belong beside this action; inert menu entries are omitted.

**Map results and detail (#256, #275)**

- Map owns one results/detail destination. Overlapping route hits open results; choosing a result replaces it with the shared detail; a single route can open detail directly. Results Back restores the exact results scroll and keeps selection/active route/camera context. Map detail pages horizontally with a native `UIPageViewController` scroll pager (interactive, cancellable, matching arrow direction, bounded neighbour cache).
- **Phone portrait (draft):** results use a native SwiftUI sheet with system presentation detents — a collapsed summary (156pt, 240pt at accessibility sizes), a content-aware opening detent and `.large` — with background map interaction enabled up through large. The opening detent is sized from the visible selected-route count (capped at half height); detail opens at about 300pt (420pt at accessibility sizes). Manual compact/large choices survive content changes. This replaces the custom 44pt pan-handle sheet on phones; native gesture feel and map/paging arbitration still need device review.
- **Wide and landscape (≥650pt wide or landscape):** a fixed regular-material edge card opens to the available height. Its explicit 44pt collapse/expand control switches between the header and full content; there is no custom pan recognizer or intermediate drag/reveal state. Results scroll, detail paging, selection and active activity survive collapse. The owner chose this option for #279 on 2026-10-03. Explicit camera fits reserve the same leading footprint in both states; collapse/expand never requests a fit.
- Camera padding is retained across navigation and applied once (automatic SDK safe-area padding is disabled). Explicit fits place the projection's principal point inside the visible rectangle, so fits work when a sheet covers the physical map centre; they wait only if the remaining viewport is unusable (<80pt). Panel resizing never triggers a fit. Route framing after selection fit and panel expansion remains under verification in #275.
- Map controls stay in one horizontal group at the viewport bottom-right; the info button and SDK wordmark stay at their normal bottom corners and are covered, never moved, by results. All source credits use the single native info menu; the Mapbox wordmark remains visible per [Mapbox attribution requirements](https://docs.mapbox.com/help/dive-deeper/attribution/), and Swisstopo permits a central source list per its [OGD FAQ](https://www.swisstopo.admin.ch/en/faq-free-geodata).

**Status (#258)**

- Routine sync status, progress, timestamps and refresh/pause live under Account → Settings → Activity Data, with Sync Details nested in Settings. Map/List reserve no persistent sync bar; Map shows no sync/loading/auth popup, including during first sync. List keeps contextual loading/recovery states; only Map-specific filtering and missing-route context uses a compact, content-sized notice.

These rules do not change route-picking/selection contracts or the [Map/List behavior contract](map-list-parity-contract.md). The shell (#254) is not complete: Stats is not yet reachable as a destination (#263), and the drafts above need owner acceptance.

## Accepted product direction

1. **Three equal primary destinations:** Map, List, Stats in a native tab bar. Keep all three mounted as needed for their retained contexts. The top bar names the destination; it has Account and Filters, without a second competing destination picker. On iPad, use the system's adaptive tab placement; the board's tab placement is illustrative, not a custom substitute for system behavior.
2. **One search/filter owner:** activity-name search above List/Stats; on Map the compact search field shares the top chrome budget. In shallow landscape or accessibility layouts collapse search to the Filters destination. Search, sport, binary and numeric restrictions apply across destinations. Stats hides date entry without a period disclaimer; browsing dates remain saved for Map/List and do not constrain Stats.
3. **Local control families:** List owns sort/display/selection/summaries. Map owns layers/camera/area selection/results. Stats owns each tile's metric, period, expansion and history. Account owns connection and detailed timestamps. No detached global row of unrelated controls.
4. **One shared detail content:** activity identity and independently available metrics, chart/gallery extension slots, fixed action area. A row or Stats activity link inspects without selecting. Checkbox/selection tools select. Show on map alone performs the explicit destination/activation/frame transition.
5. **Quiet status:** no always-visible success or old-cache warning card. Show actionable recovery once near the content it affects; retain authorized content and context. Account contains explanatory sync detail. Never use visual simplification to change retry/expiry semantics.
6. **Stats preserves its stabilized hierarchy:** Now → This year → Patterns, all ten visible tiles. Primary tiles own large headlines; Records uses its record rows without a competing aggregate headline. Native charts provide touch inspection and accessible data equivalents. No extra Rest days, totals or speed-trend screen is introduced.

These decisions establish the implementation direction. Screen-level details remain open to concrete review and adjustment; the board is not a pixel-exact specification. The acceptance record is in #252, following review of the board and locally captured authenticated web screens at Mac and iPhone viewport sizes.

## Information, colors and emphasis

Use the web's semantic vocabulary and category palette: BC/XC ski `#1982C4`, trail/hike `#FF595E`, run `#FFCA3A`, ride `#8AC926`, miscellaneous `#6A4C93`. The shared brand blue is `#1976D2`: navigation uses it as a background; the AccentColor asset uses it for foreground controls on light surfaces and the same blue family’s `#90CAF9` on dark surfaces for contrast. Selection uses a modest blue background, a checkmark and a leading mark in List, independently of sport color and inspection. List, map results and detail use the same 34pt sport badge with a 26pt symbol; touch targets stay at least 44pt. Yellow/green swatches are not small text on white. Native labels remain primary text; color is supplementary.

- **Active route:** strongest route weight + labelled active result. **Selected:** checkbox/checkmark and modest surface emphasis; hidden selected count remains explicit. **Inspected:** open detail + focus/outline/expanded context; do not imply it is selected. Destination, filter-active and selection feedback use distinct labels/shapes, never color alone.
- **Primary action:** explicit outcome with textual label, usually Show on map. **Secondary:** labelled native menu/button, neutral surface. **Destructive:** separate destructive role and appropriate existing confirmation, not sport/brand color. Successful sync is not an accent CTA.
- **List default:** compact activity name; sport + local date/time on one supporting line; distance, elapsed duration and elevation gain as inline values/units with small symbols, rather than repeated stacked labels. Selection uses explicit checkboxes separate from sport symbols. The toolbar combines selection count/actions with short Sort and Columns controls. Additional metrics remain configurable and available in detail. Default ID descending preserves contract semantics even when date order seems more familiar.
- **Detail:** headline numbers first, supporting labels/context below, matching the web card's grouping: distance with recorded speed context; moving time with elapsed time; elevation gain with independently recorded minimum/maximum; weighted power with average/maximum context. Additional recorded HR/energy/power values use the same compact grid; full recorded metadata remains reachable through a native disclosure. Do not hide one measured field because another is null. Show “—” with unavailable meaning; zero displays normally. Phone uses two metric columns, wide hosts adapt, and accessibility text uses a single column.
- **Stats:** Distance / Moving time / Elevation / Activities where supported. Time always means moving time; duration filter always elapsed. Overview uses contract display precision (whole distance/elevation, hours per contract), not List's distance-to-one-decimal precision. Legend/range labels are visible, not hover-only.
- **Surfaces:** native grouped system backgrounds for list/form/detail, restrained separators and rounded grouping. List table header and toolbar use opaque system backgrounds. Map controls and the wide Map side panel may use regular material with sufficient contrast; the phone Map sheet uses the system sheet background. Do not put every text label in a floating capsule or use material over all data cards.

## Essential journeys

**Find → filter → select → inspect → Show on map:** open List, enter a name, adjust sports/restrictions in Filters, return to the same list context, select using a checkbox, inspect using the row's content, then Show on map. Inspection does not alter selected IDs. Show on map adds and activates the target while retaining other selection and frames once. Returning restores List's sort/density/metrics/scroll anchor. The board exercises these state distinctions; production filter controls/calculations remain their owners.

**Hidden selection:** choose multiple IDs, apply a restrictive filter, show `N selected · H hidden by filters`. Visible selected routes/results obey the predicate. Clearing selection includes hidden IDs. If a Stats/other detail target is hidden by the browsing filter, offer **Clear filters and show on map** explicitly; Cancel preserves the origin and filter. The board includes this confirmation, not a silent reset.

**No GPS:** inspect and other supported actions remain available; Show on map is disabled with “No GPS route recorded.” A placeholder route must not be invented. Known photos may still exist. The reference stats fixture has no geometry; its native reference naturally demonstrates this state.

**Stats → expand → day → activity → return:** navigate to Stats with saved browsing dates; each tile retains its own reporting period. Expand Calendar, keep legend visible, choose a day (including empty days), inspect an identified activity, dismiss back to that day's context, then collapse back to the same overview anchor. Nested dismiss/back/Escape closes activity before expansion. Show on map remains explicit. No Stats link implicitly selects map/list rows.

**Old authorized offline cache:** content remains usable; Settings owns sync/offline details and informational timestamps. Server wait disables retry until deadline. List keeps contextual loading/sign-in/library recovery; Map stays clear of sync popups, with only content-sized filter/no-route notices. Real session expiry/account/deployment transition clears/fences data and derived Stats rather than showing stale authorized results.

## Stats layout handoff

Following the accepted 2026-10-04 Consistency removal, all ten visible tiles appear in source catalogue order. This supersedes the original Consistency layout and 12/52-week control requirements; its calculation fixtures remain for compatibility. Typical week retains active days per week and Activity calendar retains the activity pattern. The original prototype and capture evidence remain historical design artifacts. On phone use one readable column. On iPad use two columns at 820pt, preserving section ordering. Compact tiles are content-sized; expand via an explicit labelled corner action. Expansion stays inline. On iPad, compact tiles share equal-height two-column rows. An expanded tile replaces its original row at full width, with its compact row-mate flowing below, matching the web. Unpaired compact tiles fill their row. Tile identity remains stable during reflow so local picker/day state survives. Expansion does not force a scroll-to-top; phone and accessibility layouts remain one column. Outside scrolling/control use does not collapse expansion. Card bounds and content dimensions share one expansion progress: charts and calendar cells resize continuously, while detail regions reveal within the space becoming available. Neighboring tiles receive intermediate widths during reflow. Reduced Motion applies the final layout directly.
