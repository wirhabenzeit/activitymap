# Shared presentation and localization contract

Related issues: #420, #421, with the activity command boundary in #413. English remains the sole shipped product language; this contract prepares translation and reconciles the migrated product surfaces.

## Semantic ownership

`catalog.v1.json` owns recurring action, metric, category and message identity. Labels never decide behavior. Back, Close, Fit, Show on map, selection, activation, sharing an expiring link and GPX export remain different commands. Availability, selected/mixed state, callbacks, navigation, placement and tint stay with each platform's domain/UI owners.

Web adapters map ordinary actions to Lucide; native adapters map them to SF Symbols. Directional Back mirrors in RTL; Close, map pins, activation and vertical activity stepping do not. Export intentionally reads **Download GPX** on web and **Export GPX** on iOS. Native editing keeps the short **Save** navigation-bar label and the complete **Save changes** accessible name; web uses **Save changes** visibly. Both perform the same write.

Category IDs remain `bcXcSki`, `trailHike`, `run`, `ride`, `misc`. Their 50 sport protocol values, category membership, artwork identity and colors are UI-independent. TypeScript protocol values live in `src/contracts/sport.ts`; server adapters re-export them. `SportType` retains native wire cases. Existing aliases and category adapters remain compatible. Sport artwork in `artwork/` is deliberately shared; ordinary glyphs and layout remain native.

## Migrated surfaces

1. **Activity details and commands.** Web Map/List/Stats use an explicit activity projection and activity/command interfaces. Detail group and scoped short metric labels share terminology; missing values, measured zero/false and explicit map eligibility remain independent. Native and web edit/refresh copy distinguishes remote success, local reconciliation failure, partial photo refresh and request failure. Native detail, context-menu, sharing and edit controls consume semantic messages/glyphs while preserving native placement and dismissal behavior. Activity names, descriptions, URLs and server details stay verbatim.
2. **Navigation.** Web destinations are links with current-page semantics, keyboard focus indicators and 44px targets. The Filters trigger reports the actual mobile sheet state independently of desktop expansion. Native destination/filter/account labels, expansion state, previous/next activity actions and complete activity identification accessibility messages use resources. Native Back and explicit previous/next movement remain different actions.
3. **Status and recovery.** Web/native import coverage, scheduling, reasons, outcomes and manual Strava fetch progress use complete messages and named counts. Native browsing empty/error/recovery projections accept explicit locale; Account/Settings/Sharing status and recovery retain their existing eligibility/retry policies. A semantic `requiresSignIn` flag replaces the native status footer's display-string comparison. Initial web import errors preserve server reasons and HTTP/retry facts without concatenating English recovery fragments.
4. **Generated Stats metadata.** Tile/group titles, aggregate metric labels and option-group labels are checked against presentation messages by `generate-stats-tiles.ts`. Web generated metadata uses typed dictionary calls. Native generated definitions retain semantic tile IDs and resolve resources on demand, with explicit-locale resource accessors rather than static cached English titles.

`BrowseText` and the reusable native browsing primitives distinguish localized app resources from verbatim values. `PresentationText` provides the same Foundation-only distinction for retained editing/sharing/import controller state: resources resolve in the rendering locale; server/user content is not recursively localized. GPX preparation caches a semantic route kind (unavailable, route-only or sampled elevation); subtitle/hint resources resolve at rendering, so the cache never pins translated prose.

## Locale, formatting and preferences

Web `resolveMessageLocale` and root `html lang` share explicit English fallback. Formatting locale is independently resolved from the browser language and propagated by the display hook; unsupported product languages do not change routes, OAuth callbacks, share URLs or protocol values. Native uses String Catalog lookup with source fallback and explicit locale at render/read-model boundaries. Pseudolocales and RTL layouts are test material, not shipped languages.

SI storage, aggregation, thresholds and protocol values are unchanged. Unit preference is independent of language/formatting locale. Distance/speed retain one fractional digit; elevation retains whole units. Activity-local encoded dates use UTC/GMT as wall-time coordinates, so locale changes do not shift the activity calendar day. Fixed date patterns remain explicit user overrides. Full count messages use locale-aware number interpolation; independent import counts use complete label/value sentences to avoid concatenated plural fragments.

The native app root owns and injects an observable `DisplayPreferences` instance. There is no `DisplayPreferences.shared`. Pure formatters, Stats adapters and speed/pace presentation accept explicit units/date format/locale; views observe the injected preferences. Uninjected previews use deterministic isolated defaults. Tests use explicit locale and isolated preferences instead of mutating a singleton.

## Generation and validation

Run `pnpm presentation:generate` after catalog changes and `pnpm presentation:check` to verify. Stats metadata also requires `pnpm stats-tiles:generate` / `pnpm stats-tiles:check`. These checks participate in the existing generated/check CI gates. Generation rejects duplicate/unknown sport membership, missing messages or glyphs, mismatched named/plural arguments, missing native metric coverage and stale resources. Stats generation rejects source-copy drift between the Stats manifest and presentation catalog. TypeScript verifies exhaustive web glyph mappings.

Generated outputs are `src/lib/presentation/catalog.generated.ts`, native `Presentation.generated.swift`, `Resources/Presentation.xcstrings`, sport artwork/color metadata, and the generated Stats definitions. The legacy sport-assets script delegates to the checked generator. No localization dependency or custom universal formatting runtime was added. Native String Catalog generation retains translator-maintained target localizations and validates placeholders/plural forms; target translations must never be regenerated from English.

Shared semantic fixtures exercise zero/one/many counts and verbatim interpolation. Platform tests assert rendered meaning without demanding identical punctuation/number formatting between locales. Browser and rendered-native checks exercise compact/wide, iPhone landscape, iPad, enlarged text, selected/disabled/mixed states and RTL previews. These automated checks support the focused consistency review; they do not replace the dedicated device/assistive-technology acceptance in #387.
