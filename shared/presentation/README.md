# Presentation and localization foundation

Related open issues: #420 and #421. This is a first migration, not full issue completion.

## Contract

`catalog.v1.json` owns recurring semantic identity and source-language meaning. Action IDs describe intent; labels never decide behavior. `back`, `close`, `fit`, `showOnMap`, `clearFiltersAndShowOnMap`, `select`, and `activate` remain distinct. Selection, active map route, disabled state and mixed selection remain platform UI state, never inferred from an icon or message. `exportGPX` intentionally maps to web **Download GPX** and native **Export GPX**.

Metric IDs preserve existing web field identifiers; `iosRowID` preserves native row identifiers. Standalone metric labels provide complete accessible names (for example **Average power**, **Maximum elevation**). Short labels such as **Average** within a **Power** group are contextual variants to migrate separately. A shared `foreground` color token expresses neutral meaning; platform themes own actual colors.

Category IDs remain `bcXcSki`, `trailHike`, `run`, `ride`, `misc`. Their 50 sport protocol values remain verbatim and exhaustive. Category membership, labels, artwork identity and color are UI-independent. Web React adapters preserve `categorySettings`, `aliasMap`, `colorMap`, and `iconMap`; server exports and protocol enums are unchanged. Native `SportType` retains its cases and wire values.

Messages have stable semantic IDs, complete source sentences, named argument types, translator context and optional plural intent. The fixture contract checks IDs and arguments; each platform tests its own rendered text. The small web dictionary selects complete English plural forms through `Intl.PluralRules`; it does not interpret ICU. Native code generates literal-key `LocalizedStringResource` initializers and an Xcode String Catalog with native plural variations. Interpolated user/error content is passed verbatim and is never recursively formatted. Native `BrowseText.localized` retains the resource until rendering; `.verbatim` identifies user content. Existing String initializers remain compatibility boundaries pending call-site migration.

Native browsing consumes generated `NativeActionID` through `BrowseActionIcon` / `BrowseActionLabel`. Back, close, Show on map and GPX callers now adopt the catalog; active-route controls use explicit `iosGlyphVariants` for active and passive-badge states. The shared metadata does not own callbacks, menu membership, tint or navigation. See [the native caller inventory](../../docs/reconciliation-ios-browsing.md) for retained contextual labels and deliberate variants.

Ordinary glyphs remain platform-native: Lucide on web, SF Symbols on iOS. Back uses a directional glyph (`chevron.backward` natively; web adapters expose `mirrorsInRTL` so consumers apply CSS mirroring). Close, map pins, selection and activation do not mirror. Platform adapters are exhaustive; decorative icons remain with their component. Sport artwork in `artwork/` is a deliberate canonical asset, preserved from the accepted native/web assets. Generation checks native artwork and metadata without importing a React component. Strava artwork remains unchanged.

## Locale, units and dates

English is the sole shipped product language. Web `resolveMessageLocale` falls back to `en`, including unsupported language preferences; root `html lang` uses the same resolution. There is no URL prefix, redirect, share/auth URL change or translated-language launch. Formatting helpers accept an explicit BCP 47 locale independently of product language and safely fall back to English for invalid tags. Existing callers retain English output until they opt into a resolved formatting locale. Native String Catalog lookup uses the system locale and source-language fallback; typed resources accept explicit locales for tests.

SI storage, aggregation, thresholds and protocol values are unchanged. Unit selection is independent of locale. Measurement formatting converts once at the display boundary, retains one fractional digit for distance/speed and zero for elevation, normalizes rounded negative zero, then uses `Intl.NumberFormat` unit formatting. Native uses Foundation locale-aware formatting and the existing unit conversion scales. The stats adapter accepts locale, preserves its established precision, and uses `Intl.DateTimeFormat` instead of an English month table. Activity-local encoded dates use UTC/GMT as wall-time coordinates, so switching display locale never shifts the activity calendar day. User-selected fixed date patterns still override system ordering.

The native app root injects the observable compatibility preferences instance; Settings can receive an isolated instance. The legacy singleton remains the default for untouched formatters/stats call sites. Removing those implicit reads is explicitly deferred; new tests use isolated `UserDefaults` and explicit locale/units.

## Generation and validation

Run `pnpm presentation:generate` after source changes and `pnpm presentation:check` to verify. The latter runs in existing CI through `pnpm check:generated` and `pnpm check`. It checks duplicate/unknown sport membership, protocol coverage on both clients, missing messages/context, named/plural argument mismatches, native glyph mappings and generated drift. TypeScript checks exhaustive web glyph references. Native String Catalog generation owns English source entries and retains translator-maintained target localizations; it validates target placeholders and required plural `other` forms. Translator target edits must be committed, never regenerated from English. Unknown obsolete source message entries are removed deliberately when a source ID is retired.

Generated files: `src/lib/presentation/catalog.generated.ts`, native `Presentation.generated.swift`, `Resources/Presentation.xcstrings`, sport imageset/color metadata and artwork. The old `sync-ios-sport-assets.ts` is a compatibility entry point to the new generator. This does not change any dependencies or lockfile.

`fixtures.v1.json` includes 0/1/many counts, named verbatim interpolation, English compact, expanded pseudolocale compact and RTL wide preview intent. Pseudolocales are synthetic test material and are not shipped app languages. Native rendering tests exercise compact/wide, accessibility Dynamic Type, RTL, selected/disabled/mixed controls. The fixture-only browser suite exercises the real Strava provider/dialog through cancelled, pending/disabled and failed recovery, stable auth callbacks, then English, expanded pseudolocale and RTL screenshots. Expanded app-owned text is transformed only inside that isolated renderer fixture. The connection dialog scrolls within the viewport and its brand button scales proportionally to fit large text layouts. These are readiness checks, not final accessibility acceptance.
